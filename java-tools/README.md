# Breachwyre Java Tools

This directory contains standalone, high-performance forensic command-line interface (CLI) tools designed for the Breachwyre Enterprise Cyber Incident Response Platform. These tools are built for environments where deploying full agents is not feasible or where rapid, memory-efficient analysis of large datasets (like logs and disk images) is required directly on the target endpoint.

## Prerequisites

- **Java Development Kit (JDK) 17 or higher** must be installed on the system.
- Ensure `java` and `javac` are available in your system's `PATH`.

## Compilation

To compile the tools from source, open a terminal in this directory (`java-tools`) and execute the following commands:

```bash
javac FileVerifier.java
javac LogAnalyzer.java
```

This will produce `FileVerifier.class` and `LogAnalyzer.class` bytecode files ready for execution.

---

## Tool 1: FileVerifier

`FileVerifier` is a standalone cryptographic utility for verifying the integrity of critical forensic evidence (such as memory dumps, system logs, or captured malware samples). It streams files to compute their SHA-256 hash without exhausting system memory.

### Usage

```bash
java FileVerifier <file_path> <expected_sha256_hash>
```

### Examples

**Valid File Example:**
```bash
java FileVerifier C:\evidence\malware_sample.exe e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```
*Output will indicate `[VALID]` with an exit code of `0`.*

**Tampered File Example:**
```bash
java FileVerifier /var/log/auth.log 5d41402abc4b2a76b9719d911017c592
```
*Output will indicate `[TAMPERED]` with a mismatch warning and an exit code of `1`.*

## Tool 2: LogAnalyzer

`LogAnalyzer` is a rapid regex-based streaming parser for server logs (e.g., Apache, Nginx, IIS, Syslog). It identifies indicators of compromise (IoCs) such as SQL Injection, Cross-Site Scripting (XSS), Brute Force attacks, and Command Injection.

### Usage

```bash
java LogAnalyzer <log_file_path> [--report]
```

- `<log_file_path>`: The absolute or relative path to the log file to analyze.
- `--report`: (Optional) If provided, generates a detailed text report in the current directory containing all matched log lines.

### Examples

**Standard Console Scan:**
```bash
java LogAnalyzer /var/log/nginx/access.log
```
*Outputs a colored summary to the console detailing threat types, counts, and top suspicious IPs.*

**Scan with Forensic Report Generation:**
```bash
java LogAnalyzer C:\inetpub\logs\LogFiles\W3SVC1\u_ex231015.log --report
```
*Outputs to console and creates a file like `u_ex231015.log_breachwyre_report_20231015_143000.txt` containing full details.*

## Integration with the Breachwyre Platform

These CLI tools act as localized probes that feed data back into the central Breachwyre platform:

1.  **FileVerifier Integration:** The central Breachwyre database (MySQL) stores the baseline or "known good" SHA-256 hashes of critical system binaries and initial evidence captures. Incident responders run `FileVerifier` on endpoints, comparing local files against the hashes retrieved from the Breachwyre database. The exit codes (`0` or `1`) can be easily consumed by automated playbooks (e.g., via Ansible or PowerShell) to trigger isolation protocols if a mismatch is found.
2.  **LogAnalyzer Integration:** The detailed text reports generated by the `--report` flag are designed to be ingested by the main Breachwyre platform for further correlation and visualization. The exit code (`2` for threats detected) acts as a high-fidelity trigger for Security Orchestration, Automation, and Response (SOAR) workflows.

## Forensic Soundness Rationale

Both tools are designed with strict digital forensics principles in mind:

-   **Zero Memory Bloat (Streaming):** Both `FileVerifier` and `LogAnalyzer` use streaming I/O (buffers and `BufferedReader` / `FileInputStream`). They never load the entire file into memory. This prevents Out-Of-Memory (OOM) crashes when analyzing multi-gigabyte log files or disk images, ensuring the analysis process does not crash critical production servers.
-   **Immutability:** The tools only perform read operations on the target files (`FileVerifier` reads for hashing, `LogAnalyzer` reads for pattern matching). They do not modify the original evidence, preserving the chain of custody.
-   **Idempotency and Traceability:** Execution produces deterministic results. Detailed timestamped reporting (`LogAnalyzer`) and clear expected vs. computed hash output (`FileVerifier`) allow analysts to append tool outputs directly to formal incident reports.
